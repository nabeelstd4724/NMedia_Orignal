# NMedia Control Room — implementation assumptions

Recorded 2026-10-23 during the documentation-only audit. These are decisions for subsequent implementation, not claims that the features exist. The new admin brief takes precedence over old API/docs/messages.

1. **Current scope:** this turn performs Steps 1–2 only. Application implementation starts after the gap table is presented; no redesign, mutation, account bootstrap or data reset is part of the audit.
2. **Preserve the look:** reuse the existing graphite/lime/gold tokens, fonts, numbered sidebar, cards and components. Add reusable accessible primitives without replacing working screens wholesale. Improve contrast/keyboard/responsive defects using the existing palette.
3. **Canonical roles:** implement `user`, `editor`, `admin`, `superadmin`, with a distinct admin tier and one permission map mirrored by the UI. Migrate the unambiguous `super_admin` spelling compatibly. Preserve original stored role values and review ambiguous legacy aliases instead of automatically escalating or silently demoting users. Never use client storage as authorization.
4. **Protected staff changes:** enforce self-role/self-delete and last-superadmin protections transactionally. Reject admin mutations targeting superadmins. Do not reuse public email-matching registration as production superadmin provisioning. Existing legitimate accounts and uploaded media must be preserved.
5. **TOTP bootstrap:** when policy requires 2FA, an unenrolled staff member should receive only a restricted enrollment session after password verification, not access to admin APIs. Recovery codes are hashed/single-use. Establish an explicit safe recovery path before enforcing policy on existing accounts; do not silently disable the required superadmin default.
6. **Real data:** zero/empty is correct until real records exist. No fixture totals, synthetic charts, fake health, or simulated ad impressions. Move opt-in development fixtures to `database/seeds/`, never production UI components or repository initialization.
7. **Database ownership:** introduce new versioned migrations and a runner under the existing top-level `database/`. Do not edit applied migrations or overwrite live SQLite files. Current adapter-created auth tables need an additive compatibility migration; preserve users/sessions. Put audit insertion in the same transaction as the mutation.
8. **Publishing:** draft creation never bypasses readiness. All paths into published status use the same checklist; editors can publish/unpublish as required by the new matrix. Only an explicit person action or that person's scheduled date may publish. Never add automatic unpublishing or licence expiry.
9. **Originals versus ready video:** an uploaded container is not a ready rendition. Keep originals private, persist resumable offsets/ownership, and enforce access on manifests/segments. A local FFmpeg worker is a valid implementation; cloud hosting is not required to finish the local feature. Actual availability/codec execution must be tested later.
10. **Ad safety:** sandbox and production flows must render real creatives; test mode is explicit and separately labelled in analytics. Remote VAST validation must block local/private/metadata addresses and unsafe redirects and have bounded response size/time/wrapper depth. Do not fetch arbitrary admin-supplied URLs without these safeguards.
11. **Deferred payments:** the admin brief wins over the earlier Stripe request. Ship payments disabled and consistently flag-gate all billing/provider mutation paths. Finish manual subscription management without requesting Stripe credentials. Stripe is not a blocker to this brief's acceptance.
12. **Subscription dates:** use UTC instants and explicit start/end semantics; unexpired qualifying plans only grant premium. Evaluate expiry during entitlement checks as well as by idempotent jobs, so missed jobs cannot extend access accidentally.
13. **Admin timezone:** use a persisted IANA timezone. Until configured, default the local workspace to `Asia/Karachi`, matching this user's timezone, with an explicit UTC fallback if unavailable. Never infer dates from a different host clock. Render exact UTC/zone information for ambiguous local schedule inputs.
14. **Conflicting edits:** use record versions. Overwrite is an explicit, permission-checked new submission, never an automatic retry of a stale edit. Re-run readiness/security guards and audit the actual before/after state.
15. **Shared components first:** GLB components can ship infrastructure before dependent modules, but search/notifications remain Partial until backed by real titles/users/campaigns/reports/encode/subscription queries. Do not fabricate data to close those IDs prematurely.
16. **Privileged previews/activity:** editors may see the overview activity subset explicitly permitted by the brief but not the full Audit module, user administration or secrets. Preview identities do not create impersonation sessions (USR-08); they are bounded playback contexts.
17. **Secrets and mail:** secrets are write-only in UI/API and redacted from audits and errors. Real outbound delivery will need configured SMTP credentials, supplied through environment/settings rather than chat; tests can use a controlled local SMTP sink. A missing SMTP account blocks a real delivery check, not implementation of the settings/invitation/reset flows.
18. **Destructive actions and backups:** require named/typed confirmation, role checks, safe online SQLite backups and an automatic pre-restore backup. Test with isolated temporary databases only; never purge or restore user data during routine tests.
19. **Evidence:** each positive feature must have an actual UI-to-API flow, durable state where required and requirement-specific tests before Done. Static code presence or a green build is insufficient. USR-08 is currently Done solely as a negative source-audited requirement, with an automated prohibition regression still to add.
20. **Unverified environment:** no package install, FFmpeg/Docker execution, browser tests, SMTP delivery, npm audit or performance test ran in this audit. Prior network failures do not prove a current blocker. Check tools/connectivity at the relevant module; record exact failures rather than silently skipping acceptance.
21. **Ads media processing:** the local Ads creative worker uses the bundled `@ffmpeg-installer/ffmpeg` binary through `backend/src/media/ffmpeg.ts`; processing remains local/private, bounded to the declared Ads size/duration limits, and produces normalized MP4 plus thumbnail artifacts.
